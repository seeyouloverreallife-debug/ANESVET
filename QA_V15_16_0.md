## Browser-layer functional test
Because the runtime blocks navigation to local HTTP/file pages, full-app browser E2E could not be executed in this environment. The new UI layer was tested in Chromium using a synthetic DOM via Chrome DevTools Protocol.

Passed:
- Pilot efficiency module initializes without JavaScript exceptions.
- Contextual Continue is visible on Patient and Pre-check.
- Continue click moves Patient → Pre-check through the existing workflow-tab click handler.
- Mobile workflow status text renders (Patient / Pre-check).
- Pre-check remaining count updates.
- Focus incomplete hides a reviewed checklist item in Chromium.
- Completed checklist renders `✓ Checklist ครบแล้ว`.
- Chromium runtime exceptions from the new module: 0.

- 390×844: 4-column Continue layout rendered, no horizontal overflow.

## Safety contract
The new module does **not**:
- mark checklist items complete automatically;
- alter patient, drug, alert, or recovery data;
- bypass OR readiness;
- bypass Pre-OR Briefing;
- change dose / concentration / alert thresholds;
- change storage keys or case schema.

The `Continue → OR LIVE` action clicks the existing OR LIVE workflow control, so the existing readiness and briefing gates remain authoritative.

## Recommended device pilot checks
On the actual phone/iPad used in theatre, verify:
1. Patient → `ต่อไป` opens Pre-check.
2. Pre-check → `ต่อไป` opens Drug Calculator.
3. Drug Calculator → `ต่อไป` still opens Readiness/Briefing when required, never bypasses it.
4. `Focus เฉพาะที่ยังไม่เสร็จ` hides only completed/N/A UI rows; turning it off restores them.
5. Mobile `ขั้นตอน` dialog status badges match the current case.
6. Quick Bar does not cover the last form field when the on-screen keyboard is open.
