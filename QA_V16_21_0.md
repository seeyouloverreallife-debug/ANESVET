## Scope

Covered:

## Required real-device security acceptance
Before hospital production use with Security enabled, test at minimum:
1. Upgrade from V16.20.0 and confirm the app remains unmanaged/unlocked until the first Administrator explicitly enables Security.
2. Create the first Administrator, reload, and confirm launch starts locked.
3. Unlock with correct PIN; confirm wrong PIN is rejected and repeated failures trigger the temporary throttle.
4. Manual Lock → unlock and background auto-lock on the actual Android/Windows/iPad profile.
5. Confirm Nurse/Assistant cannot complete privileged Final Sign-off or Protocol Governance actions.
6. Confirm Veterinarian/Administrator can complete those actions only after PIN re-authentication.
7. Confirm Final Sign-off rejects an authenticated staff identity whose display name does not match the corresponding case-team field.
8. Run an active OR case through lock/unlock without losing case/timer/medication/recovery state.
9. Final Lock → Archive VERIFIED → schema-3 Full Backup → Verify File → Restore in a disposable profile.
10. Confirm restored clinical data is present but local staff PIN credentials are not restored; re-enroll local security separately.
11. Deactivate/reactivate staff and confirm the final active Administrator cannot be deactivated.
12. Repeat the complete workflow on the actual Android PWA and Windows/iPad profiles used by the hospital.
