## 7. Induction batch regression fix
Static inspection confirms:
- induction record filter accepts sources beginning with `OR Induction`

JS syntax + browser startup tests pass after change

## 8. Clinical calculation regression scope
V15.22 does not modify:
- medication calculation arithmetic
- V15.21 preparation/concentration safety gate
- ETT reference functions
- alert thresholds
- fluid calculations
- recovery scoring rules

The existing V15.21 clinical validation module remains included unchanged. V15.21 reported 15/15 matrix checks passing; this release intentionally does not alter those functions.

## 9. Browser test limitation
Direct navigation to localhost/file URLs is blocked by the execution environment administrator policy, so full origin/service-worker navigation E2E could not be completed here.

A real Chromium instance was nevertheless used with the full ANESVET DOM and controlled script injection. Reconciliation UI, Finalization Guide integration, Final Lock gate, audit creation, void behavior, stable-ID matching, and legacy-lock preservation all ran without page/console errors.

## Recommended device acceptance before production rollout
Run at least these on the devices used in OR:
1. Android Chrome — new case → induction batch → OR → Recovery → reconciliation → Final Lock
2. iPad Safari/PWA — same golden path
3. close/reopen during active OR case and verify checkpoint recovery
4. refresh after version update and confirm new service worker/cache
5. open a V15.21 locked archive and verify it stays read-only / checksum unchanged
6. custom hospital drug with duplicate planned administrations

## QA conclusion
V15.22.0 is suitable as the next test build. The principal unresolved validation item is **real-device golden-path acceptance**, not a known static/runtime defect in the new reconciliation flow.
